Programming languages are divided in 2 groups: 
1. Dynamic types
2. Static types
Statics for example: java, C#, C++ and C.
Dynamics such as: Python, JS, Ruby, PHP and...

##### The differences
In languages like JS we learnt that we can declare variables using the keywords `var, let, const`. 
When doing so, we actually aren't defining it's type to JS. We assign a num to a var, then we assign another type value to it like string, array and ... There's no limits for it.

JS only realizes the type during the runtime. So in the end we don't have to define the type because JS will do it.

In static type languages like C or C++, we need to declare the type as well. 
```cpp
int age=20;
```
In the example above, we can't assign another type value later to this variable or you can't change it's type later on.

In static languages, the code gets compiled before runtime and the bugs and errors will be found and if so, it prevents you to run the program until they are fixed.

In Js and python the bugs and errors may be found during runtime. Variables types and values will be assigned during this.
##### TS
TS helps us with making JS into a static type language. there are benefits as there are some limits.

```js
function add(a,b){
	return a+b;
}

console.log(add(20,5));
```
The function above returns us the sum of 2 variables, if for example by mistake, we use one as a numeric type and the other as a string type, the result will be different than we expected. Or num and array in a multiply function which results in `undefined` or app crash.

There are more errors that can occur during this circumstances of not defining the type of variables, functions and their arguments which can result in errors and crashes.

So we need a tool that can helps us ensure about the types. TS turns JS into a static type.
##### Other differences

| Feature         | Static Typing                                                        | Dynamic Typing                                            |
| --------------- | -------------------------------------------------------------------- | --------------------------------------------------------- |
| Type checking   | At compile time                                                      | At runtime                                                |
| Error detection | Early during the compilation                                         | During execution                                          |
| Flexibility     | Less, types must be predefined                                       | More, types can change during execution                   |
| Performance     | Usually better due to compilation time optimization                  | Potentially slower due to runtime type checks             |
| Ease of use     | More verbose, requires type declaration                              | Easier to write, more concise code                        |
| Tooling support | Good, with better auto completion, refactoring and error detection   | Limited in terms of auto completion, navigation           |
| Use cases       | Large, complex apps where safety and maintainability are priorities. | Rapid development, small to medium projects or prototypes |
