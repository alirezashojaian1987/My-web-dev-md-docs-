Generic type in TS helps us with **dynamic type checking**. When codes and type checkings become more complex, it can help us with that.

Generics syntax is different and it wasn't in JS. A little harder as well.
##### Understanding the use of Generics
We know that we can declare our vars and their types like this:
```ts
const num:number[]=[10,20,30,2,250];
const names:string[]=["Alireza","Mmd","Sobhan"];
```
Or we could do it like this:
```ts
const num:Array<number>=[10,20,30,2,250];
const names:Array<string>=["Alireza","Mmd","Sobhan"];
```
If you don't put the type and only the keyword Array, if you hover on it, you'll see that it's a generic that doesn't have any type.

So. Now we want to understand why we need generic types.
For example we want to create a function that returns the first element of an array.
```ts
const num:number[]=[10,20,30,2,250];
const names:string[]=["Alireza","Mmd","Sobhan"];
  
const getFirstElm=(input:(number | string)[]):number | string=>{
    return input[0];
};

const n=getFirstElm(num);
```
We could make separate functions for both array types(which is not recommended) or with union types, to use both of them.
But here's a problem, when using `.` besides the n element, you can't see any number class method.
Or even if you use it for the string var.

To solve this problem, we can use generic type:
```ts
const getFirstElm=<InputType>(input:InputType[])=>{
    return input[0];
}
//or
function get1stElm<T>(input:T[]){
    return input[0];
}
```
The names can be optional for the type.
Now you declared for ts to realize the type of the given input to the function, and now have access to the class methods of that element.

##### Giving two arg types
```ts
const num:number[]=[10,20,30,2,250];
const names:string[]=["Alireza","Mmd","Sobhan"];
  
const getFirstElms=<Type1,Type2>(input:Type1[],input2:Type2[])=>{
    return {first:input[0],second:input2[0]};
}

const firstElms=getFirstElms(num,names);
```
Now if you hover on the element, you can see that it shows the class types.
