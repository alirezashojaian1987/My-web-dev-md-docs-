When working on projects, we don't put all our code in one file or place, cause it can get too long resulting in hard management on code.
We don't need all our logics in one place. Like modular programming or components in React.

We can also separate our types in one file and then use them in others.
##### Import and export
In a folder we have types file and another one for using them:
`types.ts`
```ts
interface User{
    id:number;
    userName:string;
    email:string;
}
  
interface Products{
    count:number;
    list:{
        id:number;
        price:number;
        brand:string;
    }[];
}
  
export {User,Products};
```

In `index.ts`
```ts
import { User,Products } from "./types";
  
const products:Products={
    count:100,
    list:[
        {id:10,price:800,brand:"Apple"},
        {id:20,price:600,brand:"Samsung"},
    ],
};
  
const user:User={
    id:1,
    userName:"AlirezaSh",
    email:"ash@gmail.com",
}
```

Or you can use your products in another file:
`Products.ts`
```ts
interface Products{
    count:number;
    list:{
        id:number;
        price:number;
        brand:string;
    }[];
}
  
export default Products;
```
`types.ts`
```ts
interface User{
    id:number;
    userName:string;
    email:string;
}
  
export {User};
```
`index.ts`
```ts
import { User } from "./types";

import Products from "./Products";
  
const products:Products={
    count:100,
    list:[
        {id:10,price:800,brand:"Apple"},
        {id:20,price:600,brand:"Samsung"},
    ],
};
  
const user:User={
    id:1,
    userName:"AlirezaSh",
    email:"ash@gmail.com",
}
```
##### When to use `export` and when `export default`?
```ts
type Brands="Apple"|"Samsung"|"Sony";
  
type ProductList={
    id:number;
    price:number;
    brand:Brands;
}[];
  
interface Products{
    count:number;
    list:ProductList;
}
  
export default Products;
```
When your file has too many types and they are related, you only need to export one final general object. You can use export default.
