When having an `any` type var, Ts doesn't know what type of that var will be so it won't show errors when using methods from other types.

Here we used some methods from different var types.
When this program runs, it can result in error with one of the used methods.

For these situations when we don't know what our var type will be and what methods we can use, we can use `unknown` type and then the **narrowing** way we talked about to handle the different type methods.
```ts
const processInput=(input:unknown)=>{
	if(typeof input==="string")
	{
		input.toUpperCase();
	}
	
	if(typeof input==="number")
	{
		input.toString();
	}
}
```

*Note:* If it's from user defined classes, we can use this method:
```ts
const processInput=(input:unknown)=>{
	if(typeof input==="string")
	{
		input.toUpperCase();
	}
	
	if(typeof input==="number")
	{
		input.toString();
	}
	
	if(input instanceof myClass){
		//
	}
}
```

The upperhand of `unknown` towards `any` is that if your var is `any` type, compiler doesn't consider it's type at all.

`unknown` on the other hand at least makes you go through a type checking process.
