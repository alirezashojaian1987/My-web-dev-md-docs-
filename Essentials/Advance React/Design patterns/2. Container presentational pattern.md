Design pattern is divided in 2 concepts:
The container which covers multiple components.
And the presentational is the approach to present the UI.

In other words, container handles the logic, and presentational handles the UI.

They are also called **smart component**(for container) and **dumb component**(for the other).
##### Explaining the pattern
This pattern separates your component's logic into 2 distinct concerns.

Dumb component only focuses on ui and gets datas only as props. It has states, but they are local datas within the component.

On the other hand, the smart component, handles how things should work(logic, data fetching, state). It's often connected to global state, APIs, or other logic.
##### Example
For example we want to create a to do list app.
First of all, let's talk about the folder structure.
Inside the `src` folder we used to create a folder called components.

Now it's better to create a folder for a desired page first, and since that page may need multiple components, you can create a component folder there and add and design the components inside it, in order to use them in the page file.

Now, as mentioned above, we used to create components folder inside the src folder, now we can avoid that and create a folder called **shared**. We can create all the components that are shared within the pages inside this folder.
These components are better be in a more basic way, like inputs, buttons and etc.
