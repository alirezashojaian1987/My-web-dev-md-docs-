Let's now learn about next.js
Next.js is a framework that helps us create our web apps faster and better and scalable(adding more features).

It's not a library like React. This framework's base is React.
Also it's a full stack dev framework.

It has so many subjects, so we don't learn all of it here, we're currently practicing front developing.
##### What is Next.js
What we mean that it's based on react, it has the react code. All your logics from react are valid in next js.
React is a library, which is a tool that helps us to manage and handle Ui easier.
We could use states to change Dom.

React doesn't care how you handle state management, only the Ui handling mattered.

Next js adds some structure and rules and some new tools that we need to learn.
##### Next.js framework
This framework has libraries inside it such as React itself and etc.
Some tools like the router! In a next.js project we no longer need the react router dom package.

It also has a CLI that helps us run our code.

Next js can do the code splitting. In react, we need to split our codes to smaller parts with lazy loading in order when the site gets loaded, it doesn't download all of the components and pages.

Next js helps us with the faster loading.

Next js helps us render our pages better.

It has a node server. In react we only had an SPA, everything in client and SPA was managed in react and our client was the browser. All of your code runs in the browser.

Next js has the node server, so you can handle some backends.

JS can be run in two environments, one is browsers(each browser can manage Js in it's own version).
The other is the node.js server. Next js has node.js inside it, so you can run your code not only in the browser, but the server as well.

This helps with the SEO.
We can do the SSR, with the data it needs, and then send the full rendered web for the client.
##### CSR & SSR
Client side rendering, which we used to handle it in React.

Server side rendering, has some categories:
1. SSR itself
2. SSG: Static site generation
3. ISR: Incremental static regeneration
##### Review on CSR
User sends a request for the website
Server send the HTML file with JS links.
Browser downloads the HTML, it reaches the links and then downloads CSS and JS.
Then executes the framework or the library
Finally it loads the website.

In this process, user sees a white empty page at first, it's getting rendered and loaded.
##### SSR process
User requests a website.
Server creates ready HTML files.
When it does, it's not interactive at first.
Then browser downloads the JS, executes it and eventually, website becomes interactive.
