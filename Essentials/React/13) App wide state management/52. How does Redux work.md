It's a js library for managing states and maintaining them.
One of the main things about the redux is that every logic and datas are centralized which means that they are in one place so you can change any part of it you want.

Redux is flexible, it can work with react, js and some other tools as well.
The structure that redux gives us helps to debug better, predict the actions and etc. And it doesn't have any side effects.

##### How does it work?
Let's talk about how redux works step by step:
Every logic of redux gets saved in a state called `store`. All of our states are there.

Now that the states are in store, components can **subscribe** it, which means a component can get or consume the data from the store.
When store changes, component realizes and then because it's subscribing, it gets re-rendered.

Store cannot be changed directly from the component layer. It should change with a defined structure.
In order to do that, we can use `Reducer`.

States and store can be changed with the help of reducers. It can be one or many reducers.

Reducer needs an action to change or update the states. The components can dispatch the action for the reducer. Action is only the request. When reducer gets the action, it can decide on how to change or update the state.

*Note:* Reducers should only be pure functions. They shouldn't handle any side effects. Any action that enters the reducer can only have one output and that is updating an state from the store.

One of the good things about the redux is that, when a data or an state gets updated or changed, the components get only that data that is used and no unnecessary re-render occurs. Which was in Context api.
