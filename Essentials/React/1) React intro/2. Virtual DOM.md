As you remember, DOM(Document object model) was an object that browser created and read our html, css, js files and made a tree of them which is DOM.

Changing DOM is not a good option cause of the expensiveness efforts for it.

One of the most important features that React added to web dev world, was virtual DOM.
Before that let's understand the imperative and declarative.

| Imperative                                   | Declarative                    |
| -------------------------------------------- | ------------------------------ |
| How to do things                             | What to do                     |
| Statements                                   | Expressions                    |
| Defining variables and changing their values | Evaluate result based on input |
Very simple example is having an array. In imperative, you use a for loop for example to change values. In declarative, you use map. In for loop you can see what happens and you see the steps. But in map, no. Only the result matters, in other words, declarative is more about functional matter which **React** is as well. So in React we use functions more then oop.

One example uses of react is, imagine a shopping web. On top above there's a section to show whether you are signed in or no. So with React, we can define such thing for it, in other words, In react, i say if user was signed in website, show the user icon, if not, show signup / log in button.
Here we don't really know the background and only result matters. Here, virtual dom does this for us in react. Remember(If this happens, do this).

What happens?
We define a state in react. Virtual dom comes and checks the state and compares it to current web situation. If finds it, it rerenders them. Other parts of the dom are not affected. Only the changed sides.

**Virtual DOM**
```
State change -> Compute diff -> Re-render
```
