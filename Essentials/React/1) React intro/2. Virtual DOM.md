One of the first things that React solved, was changes in the **DOM**. 

As you remember, **DOM(Document object model)** was an object that browser created and then read our HTML, CSS, Js files and made a tree out of them which is called DOM.

Changing DOM is not a good option cause of the expensiveness efforts for it.

One of the most important features that React added to web dev world, was virtual DOM.
Before that let's understand the imperative and declarative.
It helped with making changes in DOM easier.

| Imperative                                   | Declarative                    |
| -------------------------------------------- | ------------------------------ |
| How to do things                             | What to do                     |
| Statements                                   | Expressions                    |
| Defining variables and changing their values | Evaluate result based on input |
Very simple example is having an array. In imperative, you use a for loop for example to change values. In declarative, you use map. In for loop you can see what happens and you see the steps. But in map, no. Only the result matters, in other words, declarative is more about functional matter which **React** is as well. So in React we use functions more than OOP.

One example for uses of react is for example, imagine a shopping website. On top above there's a section to show whether you are signed in or no. So with React, we can define such thing for it, in other words, In react, i say if user was signed in website, show the user icon, if not, show signup / log in button.
Here we don't really know the background and only result matters. Here, virtual dom does this for us in react. Remember(If this happens, do this).

What happens?
We define a state in react. Virtual DOM comes and checks the state and compares it to the current web situation and states. If it finds the differences, it re-renders them. Other parts of the DOM are not affected. Only the changed sides.
So this actually helps with a faster loading website with changes.

**Virtual DOM**
```
State change -> Compute diff -> Re-render
```
